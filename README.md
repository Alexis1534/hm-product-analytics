# Продуктовая аналитика H&M — PA-S1 «Начало работы»

Проект по дисциплине «Продуктовая аналитика», трек Б.

**Задача.** Описать продукт (омниканальная fashion-розница H&M), проверить данные, зафиксировать определения, выбрать метрики по пирамиде (North Star, две диагностические, риск), составить план трекинга и сделать первые расчёты: когортный retention и LTV/CAC.

## Что в репозитории

| Путь | Что это |
|---|---|
| `pa_s1_hm.ipynb` | основной ноутбук, разделы 1–9 тикета PA-S1 |
| `scripts/download_data.py` | скачивание данных соревнования через Kaggle API |
| `data/` | сюда попадают исходные данные; в git не входят (см. «Откуда данные») |
| `outputs/` | таблицы, которые создаёт ноутбук: сгенерированные расходы на привлечение, LTV/CAC по каналам |
| `requirements.txt` | зафиксированные версии библиотек |

## Как запустить

Нужен Python 3.10+ и около 8 ГБ оперативной памяти (Google Colab подходит).

```bash
git clone https://github.com/Alexis1534/hm-product-analytics.git
cd hm-product-analytics
pip install -r requirements.txt

# данные (один раз): принять правила соревнования на Kaggle и задать токен
export KAGGLE_API_TOKEN=<ваш токен>
python scripts/download_data.py

jupyter notebook pa_s1_hm.ipynb   # выполнить все ячейки сверху вниз
```

В Colab: выполнить в первой ячейке `!git clone ...`, `%cd hm-product-analytics`, `!pip install -q -r requirements.txt`, задать токен через `getpass` и запустить ноутбук. Если файлов в `data/` нет, ноутбук сам вызовет скрипт скачивания.

Все пути в ноутбуке относительные (от корня репозитория). Первый запуск загружает CSV в локальную базу DuckDB `data/hm.duckdb`, это несколько минут; повторные запуски быстрее.

## Откуда данные

Kaggle, соревнование [H&M Personalized Fashion Recommendations](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations), файлы `transactions_train.csv`, `customers.csv`, `articles.csv` (картинки не нужны). Данные реальные, опубликованы H&M Group; покупатели обезличены, цены нормированы.

Данные распространяются по правилам соревнования, поэтому **в репозиторий не включены**: их нужно скачать самостоятельно после принятия правил. Версий у данных соревнования нет; контроль — 31 788 324 строки покупок за 2018-09-20 — 2020-09-22.

## Что получилось

- Проверка качества: в ключевых полях покупок пропусков нет; строк покупок хотя бы с одним дефектом 0,61 % (порог задания до 5 %); пропуски в справочниках 0,1–3,7 %, заглушка почтового индекса 8,8 %. Синтетические дефекты не добавлялись.
- Определения: активный покупатель, конверсия во второй заказ за 90 дней, месячные когорты, отток «нет покупок 90 дней».
- Метрики: North Star — повторные покупатели в месяц; диагностические — конверсия во второй заказ за 90 дней и средний чек; риск — отток 90 дней активной базы.
- Трекинг: 5 событий, восстановленных из транзакций, каждое привязано к метрике и полю датасета.
- Retention: 12–16 % новых покупателей возвращаются в первый месяц, к третьему около 11 %. Покупатели канала 1 возвращаются чаще (16,1 % против 12,8 % в первый месяц), но LTV выше у канала 2.
- LTV/CAC: безубыточный CAC за 7 месяцев около 83 у.е. (канал 1) и 103 у.е. (канал 2); при сценарном CAC 50 у.е. LTV/CAC около 1,6 и 2,0.

## Синтетические данные

Сгенерированы только маржа товаров (калибровка к валовой марже H&M 52,6 % за 2019 год) и дневные расходы на привлечение (привязаны к реальному числу новых покупателей). Обоснование и таблица чувствительности — в разделах 6 и 9 ноутбука. Сгенерированная таблица расходов помечена столбцом `is_synthetic`.
